# HS-004: Empty @for Collection — Incident Report with No Incidents

## Objective

Validate DEC-001: an @for loop over an empty collection produces zero items without
error or crash. This tests a boundary condition that is easy to overlook: a
legitimately correct deck that happens to have no incidents this week.

## Scenario Description

An incident-report deck uses @for to generate one severity_cards slide per incident.
The data source returns an empty array `[]` — a valid JSON response representing a
week with no incidents.

```sf
@data incidents from "incidents.json"

slide title:
  heading "Weekly Incident Report"
  subheading "Week of 2026-05-19"

@for item in incidents:
  slide severity_cards:
    title "{{ item.title }}"
    severity "{{ item.severity }}"
    resolution "{{ item.resolution }}"

slide content:
  heading "Summary"
  bullets:
    - "No incidents this week."
```

**`incidents.json`:** `[]` (empty array)

## Expected Postconditions

1. `slideforge build incident-report.sf --format pptx,docx` exits 0.
2. Output .pptx has exactly 2 slides: the title slide and the summary slide.
3. No `severity_cards` slides appear in the output (correct: the loop generates nothing).
4. Zero validation errors, zero warnings about the empty collection.
5. The .docx report register contains body text for both slides.
6. No "empty deck" or "zero slides" warning is emitted (2 slides is not zero).

## Evaluation Criteria

| Criterion | Weight | PASS condition |
|-----------|--------|---------------|
| Build exits 0 | CRITICAL | Exit code 0 |
| Correct slide count (2) | CRITICAL | Only title + summary; no severity_cards |
| Zero errors or warnings | HIGH | Stderr contains no diagnostic messages |
| DOCX correct | MEDIUM | Report register content present for both slides |

## Information Asymmetry Note

The implementer sees BC-1.04.002 ("@for over empty collection generates zero items
without error") but does NOT see this specific integration scenario. The hidden test
is that the post-loop slide (the summary) still renders correctly after an empty
loop body — testing that empty-loop handling does not corrupt the slide stream or
the scope stack for subsequent slides.
