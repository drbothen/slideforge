# HS-014: python-pptx Migration — Existing Python Dict Deck Rewritten in .sf

## Objective

Validate ASM-008: users who currently use python-pptx can migrate to slideforge if the
DSL is easier to write than Python dicts and produces equivalent visual output. This
scenario measures migration friction by having an evaluator rewrite a representative
Python-based deck in .sf.

## Scenario Description

The evaluator is given:
1. A working Python script from `.factory/seed/reference/` that generates a 20-slide
   incident summary deck using python-pptx (the seed reference).
2. The slideforge DSL documentation.
3. A pre-built slideforge binary.
4. 30 minutes to complete the rewrite.

The Python script uses direct python-pptx API calls with:
- 5 different slide layouts
- Hardcoded color hex values (not brand references)
- Data loaded from a JSON file via `json.load()`
- A loop over incident records to generate one slide per incident
- Manual text positioning via `left`, `top`, `width`, `height` in EMUs

The evaluator rewrites this as a .sf deck using equivalent DSL constructs.

## Expected Postconditions

1. The evaluator completes the rewrite in ≤ 30 minutes without requiring author assistance.
2. `slideforge build migration-deck.sf --format pptx` exits 0.
3. Output slide count matches the Python reference (20 slides).
4. All incident data appears correctly in the slideforge output (no missing fields).
5. SSIM ≥ 0.85 per slide vs the Python reference output (allows for brand normalization differences).
6. The evaluator rates the .sf authoring experience as "easier than the Python script" in a
   post-task survey (1 = much harder, 5 = much easier; target ≥ 4).
7. Evaluator notes no more than 2 DSL concepts that required doc lookup beyond the quick-start.

## Evaluation Criteria

| Criterion | Weight | PASS condition |
|-----------|--------|---------------|
| Rewrite completed in ≤ 30 min | HIGH | Evaluator finishes unassisted |
| Build exits 0 | CRITICAL | Exit code 0 |
| Correct slide count | HIGH | 20 slides in output |
| Visual fidelity | MEDIUM | SSIM ≥ 0.85 |
| Usability rating ≥ 4 | HIGH | Post-task survey score |
| ≤ 2 doc lookups beyond quick-start | MEDIUM | Evaluator self-reports |

## Information Asymmetry Note

This is a non-must-pass user research scenario. The implementer does NOT see this
scenario or the usability rating threshold. The 0.85 SSIM threshold (vs 0.99 for
HS-009) reflects the expected visual delta from switching authoring paradigms — the
goal is "equivalent intent, equivalent output," not pixel-perfect matching to
python-pptx's manual positioning.
