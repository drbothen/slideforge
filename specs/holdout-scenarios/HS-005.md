# HS-005: Circular @include Detection — Report with Template Library

## Objective

Validate DEC-003 and FM-002: circular @include chains are detected and rejected with
a clear error that shows the full cycle. This is a Fail-Closed requirement — slideforge
must never enter an infinite include loop.

## Scenario Description

A report deck uses a shared template library that introduces an accidental circular
@include dependency across 3 levels:

**`report.sf`:**
```sf
@include "templates/header.sf"
@include "templates/sections/metrics.sf"
```

**`templates/header.sf`:**
```sf
@include "templates/shared/brand-helpers.sf"
```

**`templates/shared/brand-helpers.sf`:**
```sf
@include "templates/header.sf"   <- creates cycle: header -> brand-helpers -> header
```

**`templates/sections/metrics.sf`:**
```sf
@include "templates/shared/brand-helpers.sf"  <- also reaches the cycle via different path
```

## Expected Postconditions

1. `slideforge build report.sf` exits with code 2 (validation error).
2. E-INC-002 is emitted (circular include detected).
3. The error message shows the FULL cycle path:
   `report.sf → templates/header.sf → templates/shared/brand-helpers.sf → templates/header.sf`
4. Error includes the file:line:col for the @include directive that closes the cycle.
5. Build halts immediately on cycle detection — does NOT attempt to parse the circular file.
6. No partial output is written.

## Evaluation Criteria

| Criterion | Weight | PASS condition |
|-----------|--------|---------------|
| Exits with code 2 | CRITICAL | Not 0; not panic/segfault |
| E-INC-002 emitted | CRITICAL | Correct error code |
| Full cycle path shown | HIGH | All 3 files named in error message |
| Cycle-closing line:col cited | HIGH | File and line of the include that closes the loop |
| No partial output | HIGH | No output files written |

## Information Asymmetry Note

The implementer sees BC-1.01.004 and BC-1.06.002 (circular include detection) but does
NOT see this 3-level scenario. The hidden complexity is the second path to the cycle
via `metrics.sf → brand-helpers.sf` — the evaluator checks that detection handles a
DAG with multiple paths into a cycle, not just a simple A→B→A pair.
