# HS-007: Mermaid Diagram in PPTX — Architecture Diagram Slide

## Objective

Validate ASM-003: the Mermaid rendering engine (resolved by Spike S14) produces an
SVG that embeds correctly in a PPTX slide as a vector image. The diagram must render
visually in all four target renderers, and the SVG must pass usvg normalization (no
`foreignObject`, absolute dimensions).

## Scenario Description

A technical architecture slide deck includes a Mermaid flowchart and a sequence
diagram:

```sf
slide diagram:
  heading "Deployment Architecture"
  alt "Architecture flowchart showing three services"
  source:
    graph TD
      A[CLI] --> B[Parse Engine]
      B --> C[Eval Engine]
      C --> D[Layout Engine]
      D --> E[PPTX Exporter]
      D --> F[PDF Exporter]
      D --> G[HTML Exporter]

slide diagram:
  heading "Build Sequence"
  alt "Sequence diagram for a typical slideforge build"
  source:
    sequenceDiagram
      participant User
      participant CLI
      participant Parser
      participant Exporter
      User->>CLI: slideforge build deck.sf
      CLI->>Parser: parse(source)
      Parser-->>CLI: AST
      CLI->>Exporter: export(ir, pptx)
      Exporter-->>User: deck.pptx
```

## Expected Postconditions

1. `slideforge build arch-deck.sf --format pptx` exits 0.
2. Both diagram slides contain embedded SVG content (not rasterized PNG).
3. The SVG has no `foreignObject` elements (usvg normalization applied — BC-1.12.003).
4. The SVG has absolute width and height attributes (no percentage or viewBox-only dimensions).
5. Both diagrams are visible when the PPTX is opened in LibreOffice.
6. `alt` text from the .sf source is preserved in the PPTX shape description attribute.
7. Build time is not significantly degraded by Mermaid rendering: < 600ms total for
   the 2-diagram deck (Mermaid rendering budget ≤ 200ms per diagram).

## Evaluation Criteria

| Criterion | Weight | PASS condition |
|-----------|--------|---------------|
| Build exits 0 | CRITICAL | Exit code 0 |
| SVG embedded (not PNG) | CRITICAL | PPTX XML contains `<a:extLst>` SVG or embedded vector |
| No foreignObject in SVG | HIGH | usvg normalization verified |
| Visible in LibreOffice | HIGH | Both diagrams render without blank placeholders |
| Alt text preserved | HIGH | Shape description matches .sf alt attribute |
| Render time < 200ms per diagram | MEDIUM | Timing from --verbose |

## Information Asymmetry Note

The implementer sees BC-1.12.001 through BC-1.12.003 (diagram rendering contracts) but
does NOT see this specific two-diagram integration test. The hidden dimension is the
alt text preservation path from .sf source through the SVG normalization stage to the
final PPTX shape description — this is a cross-subsystem trace that no single BC covers.
