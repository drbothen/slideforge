# HS-002: PPTX Multi-Renderer Fidelity — Python Reference Deck Re-Authored in .sf

## Objective

Validate ASM-002: ooxmlsdk v0.6 produces PPTX files that render correctly across
PowerPoint (Office), Keynote, Google Slides, and LibreOffice with production-grade
fidelity. This is the primary multi-renderer parity test from the CLAUDE.md quality bar.

## Scenario Description

The seed reference implementation in `.factory/seed/reference/` generates a known-good
PPTX via python-pptx. This scenario re-authors the same 20-slide deck in .sf syntax
and compares slideforge's PPTX output against the Python reference output in all four
renderers.

The deck exercises the features most likely to trigger renderer-specific bugs:
- Placeholder inheritance: title, body, and picture placeholders per layout
- Color scheme application: accent colors via theme references
- Slide master + layout + slide inheritance chain (11-level precedence)
- Table element ordering (R4 finding: schema-significant element ordering)
- Notes master and handout master presence (R2 finding: required even if empty)
- Grouped shapes and image embedding
- Slide IDs starting at 256, master IDs starting at 2^31

## Input Files

**`reference-parity.sf`** (20 slides):
- 6 slide types: title, content, severity_cards, stat_callout, chart, timeline
- Brand synthesized from the Python reference color palette
- Chart data from `incidents.json` (same data as the Python reference)

## Expected Postconditions

1. `slideforge build reference-parity.sf --format pptx` exits 0.
2. PPTX opens in LibreOffice Impress without error dialogs.
3. PPTX opens in Google Slides without "unsupported feature" banners on any slide.
4. SSIM ≥ 0.92 AND PSNR ≥ 30dB per slide vs Python reference screenshots (LibreOffice headless render).
5. All color-coded elements use theme accent colors (not hardcoded hex).
6. No missing placeholders ("Click to edit title" text visible in output) on any slide.
7. Notes master and handout master present in PPTX package (`notesMaster1.xml`, `handoutMaster1.xml`).
8. `[Content_Types].xml` registers every part type (no unregistered relationships).

## Evaluation Criteria

| Criterion | Weight | PASS condition |
|-----------|--------|---------------|
| LibreOffice opens without errors | CRITICAL | No error dialog on open |
| Google Slides opens without banners | HIGH | No unsupported-feature banners |
| Visual fidelity vs reference | HIGH | SSIM ≥ 0.92 per slide |
| Placeholder presence | HIGH | No ghost placeholder text visible |
| Required XML parts present | HIGH | notesMaster1.xml, handoutMaster1.xml in package |

## Information Asymmetry Note

The implementer does NOT see this scenario. The SSIM threshold (0.92 vs the 0.99
known-good threshold in HS-009) is intentionally looser to account for brand color
mapping differences; it still tests renderer correctness. The requirement that
Google Slides shows no unsupported-feature banners is NOT documented in the PRD
prose — it is implied by the CLAUDE.md "multi-renderer parity" quality bar.
