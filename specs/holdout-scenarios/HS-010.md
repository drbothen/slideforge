# HS-010: Known-Problematic Corpus — Deck with Multiple Accessibility Violations

## Objective

Test false negative rate: a deck with known accessibility and data errors should
produce EXACTLY the known errors, no more and no less. This is the "known-problematic
corpus" scenario per the product-owner instructions.

## Scenario Description

A 10-slide deck is constructed with exactly the following known problems:

1. Slides 1-3: Each has an image with no alt text (3 × E-A11-001)
2. Slide 4: A severity_cards slide with no `label` on cards (1 × E-A11-002)
3. Slide 5: An @for loop over `{{ undefined_variable }}` (1 × E-EVL-001)
6. Slides 6-10: An `@for item in incidents:` where `incidents` from JSON is an empty list

## Input

**`problematic-deck.sf`**: Constructed as described above.

**`empty-incidents.json`**: `[]`

## Expected Postconditions

1. Build exits with code 2 (validation error).
2. Exactly 3 E-A11-001 errors reported (one per image without alt).
3. Exactly 1 E-A11-002 error reported (severity_cards without label).
4. Exactly 1 E-EVL-001 error reported (undefined variable).
5. Exactly 0 errors related to the empty @for (DEC-001: empty collection is not an error).
6. Total error count = exactly 5.
7. No output files produced (strict mode).

## Evaluation Criteria

| Criterion | Weight | PASS condition |
|-----------|--------|---------------|
| Error count = 5 (not more, not less) | CRITICAL | Exactly 5 errors in diagnostics |
| 3 E-A11-001 errors present | HIGH | Error codes and locations match |
| 1 E-A11-002 error present | HIGH | Error code and location match |
| 1 E-EVL-001 error present | HIGH | Error code and location match |
| 0 errors for empty @for | HIGH | No E-DAT-* or E-EVL-* for empty list |
| No output files | HIGH | Output directory unchanged |

## Notes

The zero-error-for-empty-@for is a specific check of DEC-001. An empty data
collection is a legitimate production state (no incidents today) and must not
produce errors. Any system that errors on empty collections is unusable for
data-reactive workflows.

False negatives (missing errors) are as unacceptable as false positives.
If any of the 5 expected errors are not reported, the validation system has
a false-negative bug that would allow broken decks to pass undetected.
