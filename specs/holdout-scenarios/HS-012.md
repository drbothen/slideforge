# HS-012: Variant-Based Export — Exec vs Technical Audience

## Objective

Validate CAP-007: a single .sf source produces two distinct builds from the same content
— an executive summary (fewer slides, higher-level language) and a technical deep-dive
(all slides, detailed data) — via the variants system.

## Scenario Description

A Q3 infrastructure review deck defines two variants with distinct include/exclude tag
logic and variable overrides:

```sf
variants:
  exec:
    include_tags: [exec, summary]
    exclude_tags: [technical, raw-data]
    vars:
      audience: "Executive"
      detail_level: "summary"
  technical:
    include_tags: [exec, summary, technical, raw-data]
    vars:
      audience: "Technical"
      detail_level: "full"
```

The deck has 30 slides total:
- 10 slides tagged `exec` (appear in both variants)
- 8 slides tagged `summary` (appear in both variants)
- 8 slides tagged `technical` (appear in technical only)
- 4 slides tagged `raw-data` (appear in technical only)

A slide uses `{{ audience }}` interpolation in its heading.

## Expected Postconditions

1. `slideforge build deck.sf --variant exec --format pptx` exits 0 with 18 slides in output.
2. `slideforge build deck.sf --variant technical --format pptx` exits 0 with 30 slides in output.
3. Executive build: slides tagged `technical` and `raw-data` are absent.
4. Technical build: all 30 slides present.
5. Heading interpolation: exec build headings contain "Executive"; technical build headings contain "Technical".
6. `slideforge build deck.sf --variant undefined` exits 2 with E-VAR-004 naming the undefined variant and listing available variants.
7. Both builds complete in < 500ms.

## Evaluation Criteria

| Criterion | Weight | PASS condition |
|-----------|--------|---------------|
| Exec variant: 18 slides | CRITICAL | Exact slide count |
| Technical variant: 30 slides | CRITICAL | Exact slide count |
| Variable override in headings | HIGH | "Executive" / "Technical" visible in respective outputs |
| Undefined variant error | HIGH | E-VAR-004 emitted with available-variants list |
| Both builds < 500ms | MEDIUM | Wall-clock timing |

## Information Asymmetry Note

This is a non-must-pass quality scenario. The implementer sees BC-1.07.001 through
BC-1.07.004 (variant contracts) but does NOT see this specific dual-build integration
test. The hidden dimension is that both variants are exercised from the same CLI
invocation session (consecutive builds) — testing that variant state is not leaked
between builds.
