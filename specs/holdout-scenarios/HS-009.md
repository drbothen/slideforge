# HS-009: Known-Good Corpus — Seed Reference Deck Translated to .sf

## Objective

Test false positive rate: a well-authored, correctly-specified deck should produce
zero errors and high-quality output. This is the "known-good corpus" scenario per
the product-owner instructions.

## Scenario Description

The seed reference implementation in `.factory/seed/reference/` contains a working
Python-based slide generator with approximately 23 slide types and sample data.
This scenario translates that reference deck to .sf syntax and verifies slideforge
produces equivalent output with zero errors.

## Input

**Reference:** `.factory/seed/reference/` Python implementation output (the "ground truth" for visual output).

**`reference-deck.sf`**: A .sf file authored to reproduce the seed reference deck:
- 25 slides covering 15+ slide types
- Brand.toml synthesized from the seed's color palette
- At least 2 @data sources (JSON files matching seed data structures)
- alt text on all images/charts
- `lang "en-US"` declared
- Correct labels on all severity_cards and status elements

## Expected Postconditions

1. `slideforge build reference-deck.sf --format pptx,pdf,html` exits 0.
2. Zero validation errors, zero accessibility errors.
3. PPTX visual regression: SSIM ≥ 0.99 AND PSNR ≥ 35dB per slide vs reference PNGs.
4. PDF passes `verapdf --flavour ua1`.
5. HTML passes axe-core (zero critical violations).
6. False positive rate = 0 (no unexpected errors on a correctly-authored deck).
7. Build time < 500ms.

## Evaluation Criteria

| Criterion | Weight | PASS condition |
|-----------|--------|---------------|
| Zero errors | CRITICAL | Exit 0; no diagnostics |
| Visual fidelity | HIGH | SSIM ≥ 0.99 per slide |
| PDF/UA-1 | HIGH | verapdf passes |
| HTML WCAG AA | HIGH | axe-core zero critical |
| Performance | MEDIUM | < 500ms |

## Notes

A well-maintained corpus producing errors would indicate a false-positive bug in the
validation system. False positives are unacceptable — they erode user trust.
