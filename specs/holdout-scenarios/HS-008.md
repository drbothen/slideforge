# HS-008: PDF/UA-1 Compliance — Complex Deck with Math, Charts, Diagrams

## Objective

Validate ASM-007 and R-003: the pdf-writer + krilla + SlideTagEngine stack produces
PDF/UA-1 compliant output for a realistic complex deck. This is the most demanding
accessibility test for the PDF exporter.

## Scenario Description

A 15-slide deck that exercises every PDF accessibility challenge:
- Title slide with heading-level structure
- Content slide with numbered list (ListItem structure tags)
- Math equations: `$E = mc^2$` and `$$\sum_{i=1}^{n} x_i$$` (display math)
- Chart slide: bar chart with axis labels and data labels (Figure structure tag)
- Diagram slide: flowchart (Figure structure tag with alt text)
- Table slide: enhanced_table with header row (Table/TR/TH/TD structure tags)
- Slide with decorative background image (must be Artifact, not Figure)
- Slide in a non-English section with `lang "fr"` on the section (v1.0: document-level lang only)
- Speaker notes on several slides (must NOT appear in PDF structure tree)

**`lang "en-US"` declared at deck level.**
**All visual elements have alt text.**
**All color-coded elements have labels.**

## Expected Postconditions

1. `slideforge build complex-deck.sf --format pdf` exits 0.
2. `verapdf --flavour ua1 complex-deck.pdf` exits 0 with `isCompliant: true`.
3. Zero veraPDF UA1 violations.
4. PDF text is searchable (pdftotext extracts body text correctly).
5. Decorative background image appears as PDF Artifact (not in structure tree).
6. Math expressions render as vector paths in PDF (not as rasterized images).
7. Chart and diagram SVG content is embedded as vector paths.
8. Document title and language are set in PDF catalog.

## Evaluation Criteria

| Criterion | Weight | PASS condition |
|-----------|--------|---------------|
| veraPDF passes | CRITICAL | isCompliant: true, 0 violations |
| Text searchable | HIGH | pdftotext extracts content |
| Math as vectors | MEDIUM | No raster images for math expressions |
| Decorative is Artifact | HIGH | Background image not in structure tree |
| Build exits 0 | CRITICAL | Exit code 0 |

## Notes

This scenario was designed around Spike S2's conclusion that pdf-writer + krilla
with a custom SlideTagEngine is the correct approach. If this fails, the fallback
is the Typst template approach (Spike S2, Option A) — a significant architecture
change that would require an ADR amendment.

The math rendering is a secondary concern (the main concern is structure tagging).
Math as vector paths is preferable to rasterization but acceptable for v1.0 if the
structure tags are correct.
