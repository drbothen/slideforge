# HS-013: SSRF Mitigation — HTTP Data Source with Allowlist

## Objective

Validate R-011: HTTP data sources with an `allowed_domains` policy block requests to
non-allowlisted domains. This is the primary SSRF mitigation for slideforge.

## Scenario Description

**Setup:** A slideforge.toml with:
```toml
[data]
allowed_domains = ["api.internal.example.com"]
```

**Deck:**
```sf
@data metrics from "https://api.internal.example.com/q3-metrics"  <- allowed
@data secret from "https://169.254.169.254/metadata"              <- blocked (IMDS)
@data other from "https://attacker.example.com/payload"           <- blocked (not in allowlist)
```

## Expected Postconditions

1. Build exits with code 2 (validation error).
2. E-DAT-006 is emitted for `169.254.169.254/metadata` (not in allowed_domains).
3. E-DAT-006 is emitted for `attacker.example.com/payload` (not in allowed_domains).
4. No HTTP request is made to `169.254.169.254` (verified via network capture or mock HTTP server).
5. The request to `api.internal.example.com` WOULD have been made (but may succeed or fail depending on whether the URL exists — this is acceptable).
6. Error messages clearly state which domain is blocked and how to add it to the allowlist.

## Evaluation Criteria

| Criterion | Weight | PASS condition |
|-----------|--------|---------------|
| No request to 169.254.169.254 | CRITICAL | Network verification (mock server sees no request) |
| No request to attacker.example.com | CRITICAL | Network verification |
| E-DAT-006 errors emitted | HIGH | Both blocked domains appear in diagnostics |
| Error message is clear | MEDIUM | Message names the domain and references allowed_domains |

## Notes

SSRF via HTTP data sources is the primary security risk for slideforge when used in
server-side contexts (e.g., a CI runner or an automated report generation service).
The allowlist must be checked BEFORE any DNS resolution or TCP connection is attempted.
Checking after connection is not sufficient (the connection itself may be the attack).

The `[data].allowed_domains` config is a security policy setting — it must not be
overridable via CLI flags (to prevent CI/CD pipeline bypass).
